# Setup interaction contract

This matrix describes local settings effects, not proof of remote access. Tests use isolated agent directories and mocked storage. Native Pi inputs distinguish an undefined cancellation from an explicit blank submission; native input placeholders are not displayed. Setup reviews use the adaptive Kit review available in the declared Kit dependency floor (verified against installed `packages/pi-sync/node_modules/@narumitw/pi-tui-kit`).

| Flow | Inputs and defaults | Save and cancellation boundary | Recovery |
| --- | --- | --- | --- |
| Initial Git | Name (`default`), existing remote (required), branch (`main`), directory (`./`), content preset, automatic sync (off first). Sessions start off. | Review full remote, whole-branch ownership, branch, directory, every included path and automatic value; one atomic connection/setup save. | Invalid remote/branch/path retries that field; Cancel saves nothing. |
| Initial WebDAV | Name, full HTTPS collection URL, username, masked password, path (`./`), content, automatic, sessions off first. | Review complete collection and path; one atomic connection/setup save. | Literal angle brackets in accepted WebDAV names/usernames/paths retain existing semantics; no password display. |
| Initial R2/S3 | Name, endpoint, region (R2 `auto`, generic `us-east-1`), explicitly entered existing bucket, path (`./`), masked credentials, content, automatic, sessions off first. | No hidden bucket default, no bucket creation. Review endpoint, region, bucket, exact path, all content and automatic choice. | Placeholder endpoints warn and retry; provider-specific bucket errors do not imply bucket creation. |
| Add connection | Valid unique label and backend address/authentication. | Separate atomic save after its own review; no network access. A saved nested connection survives cancellation of Add setup. | Invalid inputs retry in place; no rollback of an independently saved connection. |
| Add setup | Unique label, existing/new connection, backend coordinates, content, explicit automatic choice. Sessions off. | Existing connection is reread and compared under the settings lock at save; current setup does not change. | Occupied paths retry before content/review; Git requires a different branch even with a different directory. |
| Edit connection | Current address/authentication defaults, affected setup names. | Exact old/new coordinates reviewed; all affected setups use the updated connection for future access. No history is moved. | Connection contents and dependent setup list are checked again under the settings lock. |
| Edit storage location | Existing bucket/branch/path defaults, same connection. | Review exact destination; no rebind, automatic/content changes, or remote migration. | Changed connection or storage coordinates invalidate the review. Changing a Git directory requires another branch. |
| Switch setup | Explicit target and existing on-switch policy. | Existing switch confirmation and optional pull semantics remain unchanged. | Stale preview is rejected; cancellation does not silently switch. |
| Remove | Setup or unused connection, local-only confirmation. | Current setup with siblings must first be switched; an in-use connection cannot be removed. Remote history is never deleted. | Remove dependent setups first; the UI does not offer a nonexistent rebind operation. |

Required blank fields, invalid names, duplicates, control characters, unsafe paths, invalid URLs/branches, and unreplaced placeholders retry the current field. Earlier answers remain in the draft. Escape cancels that input/draft. Masked input retains the field after an empty submission and consumes split bracketed paste before submission shortcuts.

Recoverable local I/O errors (`EACCES`, `EPERM`, `ENOSPC`, `EBUSY`, `EIO`, `EMFILE`, `ENFILE`, `EROFS`) retain the exact review and require another explicit Save. Invalid settings files and stale reviews close the old review and require reopening current settings; they are never silently rebased or replaced with defaults. Existing locked, ordered, atomic writers own all publication. Cancellation cannot undo a write that already passed the atomic publication boundary.

The review component uses Kit's theme, effective bindings, hard Ctrl+C cancel, non-selectable text viewport and adaptive height. A nested review cancellation returns to its owning menu; session replacement/shutdown aborts the entire owning flow. Tests cover 32/48/80 columns and 16/24 rows, scrolling, remapped confirm/cancel, disposal, stale save and retry. Native input layout/edit semantics are intentionally retained rather than replaced with another wizard framework.

## Diagnostic outcome contract

S3 Check setup performs a signed GET of the selected setup's latest pointer, with a ten-second total deadline and bounded error body. It never lists buckets or performs PUT/DELETE. HTTP success proves only that this GET succeeded, not snapshot validity or write access. An explicit `NoSuchKey` means no snapshot at the requested path; `NoSuchBucket` reports a missing bucket. Other 404 responses remain ambiguous. HTTP 401/403 points to credentials/permissions; timeout and transport failure point to address/network checks. Provider response bodies and credential values are not printed by this probe. Existing R2 temporary-token fallback remains intact.

Git explicitly reports that remote write access is untested. WebDAV retains its write/cleanup probe and repairs a missing active-snapshot history entry; menu descriptions and diagnostic output disclose both effects. These existing WebDAV writes are tested only against disposable mock storage. Global secret-scan and on-switch settings remain global. Automatic sync applies to the current setup at session startup; shutdown pushes only when automatic sync and session inclusion are both enabled.

## Evidence owners

`setup-defaults`, `setup-guidance`, `setup-name-ui`, `occupied-setup-location`, `git-ui`, `webdav-ui`, `webdav-input-compatibility`, `settings-management`, `review-feedback`, `setup-review`, `setup-save-review`, `secret-input`, `menu-wording`, `s3-diagnostics`, `sync-storage`, `backend-lifecycle`, `custom-lifecycle`, and `build-runtime` tests cover the matrix together. Tests capture custom callback observations and assert after completion where menu error handling could swallow assertions. Six checked-in `fixtures/setup-review-<width>x<rows>.txt` frames record initial and scrolled-to-end views. Root checks and tests remain required; this contract is not a substitute for their results.

A controlled package-directory smoke ran `pi --mode rpc --no-session --no-extensions --no-skills --no-prompt-templates -e ./packages/pi-sync` after building. With temporary HOME/agent settings and a `get_commands` readiness handshake, the real Pi/Jiti process opened seven manager/connection frames, preserved the exact Git remote, cancelled back through the menus, made zero provider requests and left settings byte-for-byte unchanged. `build-runtime.test.ts` additionally exercises the generated initial-setup lazy boundary through Pi's resource loader. Native input and Kit TUI harness tests cover first setup, add/edit, switch/remove, corrections, save retry and cancellation. Live provider credentials and production remotes are intentionally not exercised.
